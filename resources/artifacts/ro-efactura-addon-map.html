Overview

An invoice that declares ro-efactura-v1 is corrected and checked inside GOBL, before any XML exists. Calculate runs the normalizers, which quietly fix what can be fixed. Validate runs the rules, which refuse what ANAF would refuse, each with a code like GOBL-RO-EFACTURA-BILL-INVOICE-13. A document the addon accepts is one the converter can render and ANAF's schematron will take.

Every GOBL invoice type maps to the Romanian code ANAF files it under: 380, 381, 384, 389 or 751. Proformas are skipped and debit notes refused.

How the layers stack

Each layer builds on the one above it and knows nothing about the jobs of the others. This page covers the highlighted one.

GOBL coregobl v0.507

Invoice types, calculation, rounding, the self-billed tag, generic validation. There is no Romanian tax regime yet, so core does not know that RON is the accounting currency or what a valid CIF looks like.

eu-en16931-v2017required by the addon

The European standard: UNTDID document types and payment means, VAT categories, VATEX exemption codes and the BR rules. Declaring the Romanian addon pulls it in automatically.

ro-efactura-v1addon/ · this page

Everything Romania adds on top: document types, rules, normalizers, tags, the CNP identity and the county and sector codes.

convertermodule root · its own page

Renders the accepted invoice as CIUS-RO UBL and reads received UBL or CII back to GOBL. It relies on the addon having done its job first.

Document types

The addon's scenarios write the Romanian code (BT-3) into tax.ext.untdid-document-type from the invoice type and its tags. When two match, the later one wins, so self-billing beats accounting. KindOf gives the same answer before the invoice is calculated, so a caller can drop what ANAF never receives.

A storno is a standard invoice with a negative total, so it stays 380. A credit note or corrective invoice issued by the buyer keeps 381 or 384; self-billing then only adds the mention and changes how ANAF receives it.

Silent fixes that run on Calculate, before any rule. Each one removes a whole class of rejection instead of reporting it.

Helpers

Questions the addon answers for the converter and for gov-ro's routing. A change here changes how ANAF receives invoices.

FunctionAnswers
IsSelfBilledDoes the invoice carry the self-billed tag?
IsSelfSupplyIs it self-billed with the same CIF on both sides: a company billing a supply to itself?
IsBuyerIssuedIs it self-billed by a different company, the case that needs the mention and autofactura?

Gaps and decisions

Only what changes how the addon behaves today.

Gap

GOBL has no Romanian tax regime

Nothing checks that a CIF is well formed, and the standard VAT rates live in the addon instead of GOBL core. When GOBL gets a Romanian regime, both should move there and the rate rule can go.

Decision

Foreign buyers need their own identifier

GOBL cannot tell a foreign company from a foreign person. So a buyer abroad without any identifier is refused instead of being sent as an anonymous consumer. This stops a company from being filed as B2C. The cost: a foreign tourist without an ID is refused too, although ANAF would accept thirteen zeros for a person.

Gap

Address rules on the ordering seller

Two rules require a street and a city on the ordering seller. The converter now writes that party as the tax representative, which ANAF does not check this way, so these rules are stricter than ANAF.
