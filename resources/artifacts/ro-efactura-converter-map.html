Overview

The converter is the glue between GOBL and ANAF's XML. The addon decides what a Romanian invoice must say. gobl.ubl and gobl.cii decide how XML is written and read. The converter runs them in the right order and fixes the few Romanian details the format libraries cannot decide on their own.

Done

ForwardConvert

Takes a GOBL envelope and returns CIUS-RO UBL, ready to upload. Used by gov-ro's generate action.

Done

ReverseConvert

Takes the XML from an ANAF download, UBL or CII, and returns a calculated GOBL invoice with the Romanian addon applied. Used by gov-ro's import action.

Round trip

An invoice leaves as GOBL, travels through ANAF as XML, and comes back as GOBL. The tests close the loop: they render the invoice read back and expect the very same XML.

flowchart LR
  A[GOBL invoice] -->|ForwardConvert| B[CIUS-RO XML]
  B -->|upload| C[ANAF seals it]
  C -->|download| D[XML from ANAF]
  D -->|ReverseConvert| E[GOBL invoice]
  E -.->|ForwardConvert in tests| F[identical XML]

Most of the trip is lossless. CIUS-RO has no place for a few GOBL fields, so the GOBL read back can differ in those. The XML never does, apart from one invoice listed under the tests.

Sending: ForwardConvert

  1. Copy the envelope, so the caller's silo document is never changed.
  2. Ask KindOf whether ANAF takes this kind at all. A proforma stops as skipped, a debit note as unsupported.
  3. Calculate and validate, so every addon fix and rule runs. A broken rule stops here with its code.
  4. gobl.ubl writes UBL using ContextCIUSRO, which sets BT-24 to …CIUS-RO:1.0.1 and names the schematron the result is checked against.
  5. localize adds the Romanian details, then the XML is serialized.

Receiving: ReverseConvert

  1. Look at the root element to tell UBL (Invoice or CreditNote) from CII. Anything else is unreadable.
  2. UBL is read by gobl.ubl as Romanian, whatever CIUS-RO version the file names. CII is read by gobl.cii, then the Romanian addon is declared on the result, because gobl.cii cannot be told.
  3. Note what the parsers drop: the document type code, the payment means code, attachment file names and the VAT total in each currency.
  4. delocalize puts back what CIUS-RO and the parsers lost.
  5. Calculate with the addon. The invoice is never validated: an invoice ANAF already sealed is kept even if it breaks one of our rules.

Localize and delocalize

Every change made on the way out has a partner that undoes it on the way in. When you change one side, check its partner.

On the way outOn the way in
The addon files an accounting invoice as 751 and a self-billed one as 389.⇄Document type: 751 becomes a standard invoice with the accounting tag, which both parsers miss. 389 gets its self-billed tag back, which gobl.ubl drops when it keeps sealed totals.
Outside scope: for a seller not registered for VAT, the seller's CIF moves to BT-32 and BT-30, and the buyer's to BT-47.⇄Outside scope: those CIFs become tax identifiers again. A buyer ID that is a CNP or not purely numeric, such as a trade register number, stays as it is.
Tax currency: a foreign-currency invoice gets BT-6 = RON and its VAT in RON (BT-111), from the invoice's exchange rate.⇄Tax currency: the rate is worked out again as VAT in RON ÷ VAT in the invoice currency, to four decimals as BNR publishes it.
The addon writes a consumer's CNP as the buyer's legal ID. The XML keeps the number but not its type.⇄Parties: a bare 13-digit legal ID is typed as a CNP again.
gobl.ubl writes tax numbers with their country prefix (RO12345674) under the VAT scheme.⇄Parties: the country comes from the prefix, and the extra VAT label the parsers add is dropped.
The exact payment means code is written (BT-81), such as 26 for a holiday voucher.⇄Payment: codes the parsers cannot map are put back instead of turning into 1. A SEPA creditor ID left on the seller moves back to the direct debit.
An attachment's file name is written next to its URL.⇄Attachments: the file name gobl.ubl drops is restored by URL.
The schema location and the NA purchase-order placeholder are dropped.→Nothing to undo: the parsers ignore both.
The addon adds the Autofactură note and copies the enforcement body's CIF to BT-60.→Read back as an ordinary note and identity. The tags they came from are not guessed.

What cannot come back

CIUS-RO has no place for these GOBL details. The original XML is always stored next to the imported invoice, so nothing is lost legally.

Gaps and decisions

Only what changes how the converter behaves today.

Bug

Seller outside the VAT scope with an ordering seller

When an invoice in category O also has an ordering seller, localize writes the ordering seller's CIF into the seller's fields. gobl.ubl now writes the supplier as the seller, so the CIF is the wrong one. The fix is to always use the supplier. No corpus invoice has this combination yet.

Decision

Sealed totals are kept as stated

When a received invoice's totals do not add up, gobl.ubl and gobl.cii keep the totals ANAF sealed and mark the invoice bypass. The converter adds no totals check of its own and never validates a received invoice.

Decision

No guessing tags the XML does not carry

Enforcement, and self-billing on a 381 or 384, only exist as ANAF upload flags. Reading them back would be a guess, so the converter leaves them off.

Gap

No exchange rate on a zero-VAT foreign invoice

The rate is only recoverable from the two VAT totals. With zero VAT both are zero, so the invoice comes back without a rate. It imports fine, but could not be sent again as it is.

Temporary

gobl.cii runs on a fix branch

Reading the VAT in RON from CII needs the gobl.cii fix that is still in review. The module is pinned to that branch until it is released.
